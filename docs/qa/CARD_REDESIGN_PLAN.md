### מה כן עובד ולא אגע בו

הפעולות המהירות נגזרות ממקור אמת יחיד (`contact-source.ts`), הווידג׳טים
מודולריים וניתנים לסידור, ה‑vCard מסונכרן, השיתוף עובד עם fallback,
`SafeImage` מונע אייקון תמונה שבורה, וה‑RTL/LTR כבר מוזן משפת הכרטיס.
**BENCH-002, BENCH-005 ו‑BENCH-006 מתקיימים כבר היום.**

## 2. עקרונות העיצוב — שפה מקורית ל‑NAIMLY

ארבעה עקרונות שמהם ייגזרו כל ההחלטות:

1. **הקפל הראשון מוכר.** שם, תחום, מיקום ופעולה אחת — בלי גלילה.
2. **פעולה אחת ראשית, לא חמש שוות.** שורת הפעולות משנית ל‑CTA.
3. **מקטע ריק אינו מוצג.** לעולם לא כותרת מעל תוכן שאין.
4. **הצבע של הלקוח מנצח.** המותג שלנו במעטפת; הכרטיס עצמו הוא שלו.

**מה שמבדיל אותנו ויזואלית** (ולא מועתק): טיפוגרפיה עברית‑ראשונה עם
Rubik במשקלים 800/900 לכותרות, פינות א‑סימטריות, ספריית 119 הרקעים
שכבר קיימת כנכס ייחודי, ושכבת צבע שנגזרת מ‑`--card-primary` של הלקוח
דרך `color-mix` — כך שכל כרטיס נראה שונה בלי תבנית נוספת.

## 3. המבנה המוצע

```
PublicCardClient
└── CardSurface                 ← עטיפה, רקע, טוקנים, dir/lang
    ├── CardHero                ← וריאנט לפי template
    │   ├── CoverLayer          ← קאבר / רקע / גרדיאנט
    │   ├── IdentityBlock       ← לוגו, שם (H1), תפקיד, מיקום
    │   └── AvailabilityBadge   ← נגזר משעות פעילות (A-4)
    ├── PrimaryCta              ← WhatsApp / שיחה / ליד / פגישה  (A-2)
    ├── QuickActionRow          ← קיים, נשאר כפי שהוא
    └── CardSections            ← מפה לפי widget.type
        ├── SectionShell        ← כותרת + מצבי empty/error
        ├── AboutSection … FilesSection … ContactSection
```

**רכיבים חדשים: 11. רכיבים שיוסרו: 0.** `card-preview.tsx` יתפרק
למקטעים; ה‑API של `CardPreview` יישאר זהה כדי שהעורך והתצוגה החיה
לא ישתנו.

## 5. מיגרציה

`021_card_primary_cta.sql` — הפיכה:

```sql
alter table public.cards
  add column if not exists primary_cta jsonb not null
  default '{"type":"whatsapp","label":"","value":""}'::jsonb;
```

ברירת המחדל משחזרת את ההתנהגות הקיימת בדיוק, ולכן כרטיס קיים אינו
משתנה. `template` כבר קיים במסד — רק נתחיל לקרוא אותו.

## 6. בדיקות

- **יחידה:** בחירת תבנית, גזירת ה‑CTA, תג הזמינות משעות הפעילות, מקטע ריק.
- **E2E:** הרחבת `e2e-check.mjs` — H1 יחיד, אין `#`, אין חריגה אופקית.
- **רוחבים:** 360 / 390 / 430 / 768 / 1440 (ראו שאלה ש‑4).
- **רגרסיה:** שלושת כרטיסי התצוגה חייבים להיטען ולקבל פניות אחרי השינוי.
