# NAIMLY / נעיםלי — מערכת ישראלית שהופכת היכרות לליד

מערכת Web מלאה בעברית וב־RTL, שבה בעל עסק נרשם, בונה כרטיס ביקור דיגיטלי, מפרסם אותו בכתובת אישית, משתף QR, מקבל פניות וצופה באנליטיקה. הפרויקט בנוי ב־Next.js, TypeScript, Tailwind CSS ו־Supabase ומוכן לפריסה ב־Vercel.

> **מותג ברירת המחדל:** NAIMLY / נעיםלי, עם הדומיין המיועד `naimly.co.il`. זמינות דומיין עשויה להשתנות עד לרכישה; מומלץ לבצע גם בדיקת סימן מסחר לפני השקה מסחרית. את פרטי המותג והמחירים משנים במקום מרכזי אחד: `src/lib/config.ts` או באמצעות משתני הסביבה.

- אתר שיווקי, מחירון, FAQ ועמודי אמון.

- 3/6/9 פעולות חכמות ל־WhatsApp, טלפון, אימייל, Waze, Google Maps ורשתות.
- טופס לידים דינמי וחיבורי Google Analytics, Tag Manager ו־Meta Pixel לאחר הסכמה.

- 14 ימי התנסות עם **כל היכולות פתוחות** וספירה לאחור חיה.
- חסימה מלאה בתום ההתנסות, עם הסבר ומסלול רכישה.

- אכיפת מסלולים בשלוש שכבות — ממשק, route ו־trigger ב־Postgres.

- מסך ניהול לאישור תשלומים, פתיחת חשבונות ושליחת פרטי כניסה.

## הרצה מקומית

דרישות: Node.js 20.9 ומעלה ו־npm (Next 16 לא רץ על Node 18).

```bash
npm install
cp .env.example .env.local
npm run dev
```

ללא משתני Supabase המערכת פועלת אוטומטית ב־**מצב הדגמה**. כל המסכים נגישים, עורך הכרטיס עובד והנתונים נשמרים מקומית רק לצורך ההדגמה.

## חיבור Supabase

1. יוצרים פרויקט חדש ב־Supabase.
2. פותחים את SQL Editor ומריצים לפי הסדר את הקבצים בתיקייה `supabase/migrations`.
3. מעתיקים את שלושת המפתחות המתאימים אל `.env.local` לפי `.env.example`.
4. ב־Authentication > URL Configuration מגדירים:
   - Site URL: כתובת האתר.
   - Redirect URL מקומי: `http://localhost:3000/auth/callback`.
   - Redirect URL בפרודקשן: `https://your-domain.com/auth/callback`.
5. לפתיחת מנהל מערכת ראשון, מריצים לאחר הרשמתו:

```sql
update public.profiles set role = 'admin' where email = 'your@email.com';
```

המיגרציה יוצרת טבלאות, אינדקסים, טריגרים, מדיניות RLS ודלי אחסון ציבורי בשם `card-media`.

## חיבור סליקה

בפיתוח `PAYMENT_PROVIDER=mock`, ולכן לא מתבצע חיוב. בחיבור ספק אמיתי מגדירים `PAYMENT_PROVIDER=custom`, כתובת API וסוד.

המערכת שולחת לספק בקשת `POST` ובה לקוח, סכום, מטבע, מחזור חודשי, כתובות הצלחה/ביטול ו־Webhook. הספק צריך להחזיר:

```json
{
  "sessionId": "provider-session-id",
  "checkoutUrl": "https://provider.example/checkout/..."
}
```

ה־Webhook נשלח אל `/api/payments/webhook` עם כותרת `x-payment-signature` המכילה HMAC-SHA256 של גוף הבקשה באמצעות `PAYMENT_WEBHOOK_SECRET`.

מבנה האירוע מפורט ב־[מסמך הפריסה](docs/DEPLOYMENT.md). לאחר בחירת ספק בפועל, מחליפים רק את שכבת ה־Adapter ב־`src/lib/payments.ts` בלי לשנות את מסכי המערכת.

## העלאה ל־Vercel דרך Git

1. דוחפים את התיקייה למאגר GitHub/GitLab/Bitbucket.
2. ב־Vercel בוחרים **Add New Project** ומייבאים את המאגר.
3. Framework Preset מזוהה אוטומטית כ־Next.js.
4. מוסיפים את משתני הסביבה מתוך `.env.example`.
5. לוחצים Deploy ומעדכנים את כתובות ההפניה ב־Supabase.

פקודת הבנייה היא `npm run build`. אין צורך ב־Vercel configuration נוסף.
